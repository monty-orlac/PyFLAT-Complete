# PyFLAT Complete 開発者向け情報

本ファイルは、PyFLAT Complete のソースコードを読む・改造する・テストする方向けの情報をまとめたものです。プログラムの使い方については [README.md](../README.md) を、データ構造やアルゴリズムの解説については連載記事をご参照ください。


## 開発環境
開発には下記のバージョンを使用しています。

- Python 3.14.6
- NumPy 2.5.1
- SciPy 1.18.0
- scipy-stubs 1.18.0.1
- numba 0.67.1

scipy-stubs は SciPy に型ヒントを導入するための開発補助パッケージであり、プログラムの実行には必要ありません。VS Code エディタでコードを書く際の自動補完や、実行前の型エラーチェックを目的として導入しています。

### 動作環境の要件について
README に記載している動作環境の要件は、下記の理由によるものです。

- Python 3.12 以降 ... Python 3.12 で導入された型パラメータ構文 (`class Foo[T]: ...`、`def foo[T](...)`) と `type` 文を使用しているため。
- NumPy 2.0 以降 ... NumPy 2.0 を前提としており、SciPy、Numba もそれに対応したバージョンが必要になります。

必要なパッケージとそのバージョンは `src/metadata.py` の `__requires_python__`、`__dependencies__` で定義しており、プログラム開始時にこれらを確認しています。要件を変更する場合は、README の記載とあわせて更新してください。


## ソースコードの構成
実行の起点となるのは `src/pyflat.py` です。下記、主要なフォルダやファイルを紹介します。
- `src/linalg`フォルダ: 線形代数ソルバーを格納するフォルダ。linalg_base.py でインターフェースを宣言し、それを継承する形で各種ソルバーが実装されています。
- `src/fe` フォルダ: 節点や要素など、有限要素法に関連するコードを格納するフォルダ。
- `src/fe/lib` フォルダ: 要素剛性行列の構築など、有限要素法のアルゴリズムを独立した関数として実装しているフォルダ。`src/fe`フォルダのコードから内部的に呼ばれる。
- `src/card_reader.py`: 本プログラムが想定している構造化されたテキストファイルを読むための汎用ファイルリーダー


## 機能の追加
### カード (材料特性・要素特性・要素・荷重境界条件) の追加
入力ファイルのカードは、対応する基底クラス (`MaterialBase`、`PropertyBase`、`ElementBase`、`BaseCondition`) のサブクラスとして実装します。サブクラスにクラス変数 `TYPE` (カード名) と書式指定子を返す `get_card_initializer()` を定義すると、`pyflat_main.py` がサブクラスを自動で収集してカードとして登録します。そのため、読み込み処理を変更する必要はありません。ただし、自動収集の対象になるのは import 済みのモジュールに定義されたクラスだけなので、新しいファイルにカードを実装した場合は `src/fe/__init__.py` にその import を追加してください。

書式指定子の書き方は `src/card_reader.py` のモジュール docstring を参照してください。

### 線形代数ソルバーの追加
`IGenerator` のサブクラスにクラス変数 `TYPE` (ソルバー名)、`DESC` (説明文)、`NEEDS_REORDER` (自由度の割り振りが性能に影響するかどうか) を定義し、`src/linalg/__init__.py` で import すると、`--solver` の選択肢に自動で追加されます。

### 要素計算関数 (`src/fe/lib/`) の方針
`src/fe/lib/` の要素計算関数は、座標や弾性係数マトリクスなどの入力値だけから結果を計算する独立した関数とし、モデルデータのクラスには依存させない方針としています。ヤコビアンの行列式のチェックなどのエラーチェックも、共通関数に切り出さずに各関数の中に記述しています。


## 回帰テスト
`tests` フォルダには、入力ファイル (`*.in`) と、それを実行したときの期待出力 (`*.out`) が収録されています。期待出力は、リポジトリ直下から下記のコマンドで作成したものです (オプションは `--validate --verbose` のみで、他はデフォルト値)。
```batch
  > python src\pyflat.py tests\model_patch_PEQUAD4.in --validate --verbose > tests\model_patch_PEQUAD4.out
```
`--validate` を指定すると、バージョン情報や実行時間など実行環境によって変わる情報が出力されなくなるため、出力をそのままファイル比較できます。

全テストをまとめて実行して期待出力と比較するには、リポジトリ直下で下記の内容のバッチファイルを実行します (Windows)。
```batch
@echo off
for %%f in (tests\*.in) do (
    python src\pyflat.py %%f --validate --verbose > "%%~dpnf.new"
    fc "%%~dpnf.out" "%%~dpnf.new" > nul && echo OK: %%~nxf || echo NG: %%~nxf
)
```
実行結果は `tests\*.new` に保存されます (`.gitignore` によりリポジトリには含まれません)。NG となったテストは `fc` で差分を確認してください。

なお、期待出力には入力ファイルのパスが `tests\model_patch_PEQUAD4.in` のように記録されています。Windows 以外の環境で実行すると、パスの区切り文字が異なるため、この1行だけ差分が出ます。

プログラムの変更により計算結果が意図的に変わる場合は、上記のコマンドで期待出力を作り直し、git の差分で変更内容を確認してからコミットしてください。


## Numba の JIT コンパイル結果のキャッシュ
`SKYLINE` ソルバーは初回実行の際に Numba による JIT コンパイルが行われてコンパイル結果をキャッシュします。この処理にはだいたい 1 秒程度の時間がかかります。
キャッシュは `__pycache__` フォルダに `*.nbi`、`*.nbc` ファイルとして保存されます。zipで固めた  `.pyz` として実行する場合はキャッシュを置く場所がないため、エラーとなりますので、キャッシュを無効に変更します。キャッシュを無効化するには、`src\linalg\linalg_skyline.py` に含まれる `@numba.njit(cache=True)` デコレータを
```Python
@numba.njit
```
と変更します。


## 改行コード
リポジトリでは `.gitattributes` の `* text=auto` 指定により、テキストファイルの改行コードを LF に統一して管理し、チェックアウト時に各 OS の改行コードに変換します。`.gitattributes` を追加する前からあるファイルの改行コードを揃えるには、追加後に一度下記を実行してコミットしてください。
```batch
  > git add --renormalize .
```
